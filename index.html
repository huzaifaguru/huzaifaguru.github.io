01 — case study

Click-decay scoring for FlyRank

FlyRank ML Internship — Lane 4, CTR / Engagement Opportunity Scoring

§1 the problem

FlyRank tracks 11,119 pages across 28 clients. Reviewing all of them by hand to catch underperformers would take about eleven years. Some pages keep their search rank but still lose clicks compared with other pages getting the same exposure — a decline nobody notices because the rank never moves. The task: find those pages without a human reading through all 11,119.

§2 what I did

  • Built a baseline first, not a model: a hand-written rule that ranks each page against the median click-through rate of pages with similar impression volume, scores the shortfall, and weights it by log impression volume.
  • Tested four learned models against that rule — logistic regression, a depth-3 decision tree, random forest, gradient boosting — instead of assuming a model would win by default.
  • Validated with client-grouped 5-fold cross-validation on 8,825 pseudonymized pages and 44 features, instead of random splits. Random splits underestimated uncertainty by 1.9× to 2.8×, so the weaker statistical power was the honest trade to make.
  • Dropped 90-day CTR aggregates overlapping the outcome window and excluded outcome/production flags, so the model couldn't see the answer before making the call.

§3 what came of it

  • Zero of four models beat the rule at K=50. Left alone, the depth-3 tree re-derived the rule's own logic.
  • Where the models earned their place: reaching 44 of 6,053 low-volume pages the rule structurally couldn't see — it flagged zero of them.
  • 42% of flagged pages recover on their own within 30 days, no fix applied — which is why this project attaches no value estimate to any fix.

Directional, not decisive: rule and model are statistically indistinguishable on precision. The model's real value is reach into low-volume pages. The 42% baseline recovery rate means this is a triage tool, not a fix-and-measure pipeline.

02 — selected projects

IronShield: real-time fraud & mule-account detection

IBM Z Datathon 2026 · team lead · XGBoost · TreeSHAP · LinuxONE (s390x)

Scores every payment before the money moves, flags mule rings from a live transaction graph, and explains each alert in plain English. Account IDs are pseudonymized with HMAC-SHA256 before analysis. On a time-ordered held-out split: 96.3% precision, 92.1% recall, 19/19 mule rings caught, 0.087 ms median decision time. The data is synthetic, so these numbers show the system works end to end. They aren't a real-bank result.

Premier League match outcome predictor

Python · XGBoost · Dixon-Coles · walk-forward CV · Streamlit

Models from logistic regression to a time-decayed Dixon-Coles goals model, trained on 26 seasons and tested once on 1,140 held-out matches against the bookmakers' own forecast. The best model reaches log loss 0.976 against the bookmaker's 0.966, a statistically clear gap, so no model is as accurate as the professional forecast. An Elo-only model comes within 0.006 of the full 65-input model.

Supreme Court of Pakistan judgment analytics

Python · pdfplumber · Pandas · scikit-learn

Turned ~1,200 raw judgment PDFs into a 25-field table using hand-written regex extraction. Auditing my first pass showed its 94% accuracy just reflected the majority class, so I rebuilt everything after extraction: proper deduplication (1,189 rows down to 1,041 cases), no fake "unknown" labels, and a classifier measured against a majority-class baseline. Includes an interactive dashboard and a similar-case search.

Formal verification of a neural network

CT-354 Machine Learning, NED · 3-person team · PyTorch · PuLP/CBC MILP

Implemented the SHERLOCK algorithm (Dutta et al., 2018) to prove guaranteed output bounds for a ReLU network predicting CO concentration on the UCI Air Quality dataset. It combines gradient-based local search with an exact MILP solve, which gives a mathematical certificate instead of an error bar.
